# 自动跟随滚动重构 Spec v2：取消手动开关（几何自愈 + 位移确认 + 追赶式缓动）

> v1 起草：2026-09-16；**v2 定稿：2026-09-17**（待 sonnet 复审，未实施）
> 机制来源：[DeepSeek流式自动滚动机制与Vue3复刻](2026-09-16_DeepSeek流式自动滚动机制与Vue3复刻.md)
> v2 修订：吸收 opus / sonnet / haiku / fable 四份独立评审的全部 P0 与高置信 P1（修订点在文中以 **[v2]** 标注）
> 范围：仅前端 `frontend/`，仅新版页 `/`（`pages/index-original.vue` 的 Classic UI **不在范围内**，见 3.3）

## 一、背景与目标

### 现状问题

当前实现（`useScrollSync.ts` + 手动开关）有四类问题：

1. **手动开关体验差**：`configAutoScroll` 是持久化配置开关。直播进行中用户上滚回看旧字幕，下一次数据更新立即把视口拽回底部——想安静阅读必须先手动关开关，看完再手动开。
2. **定长动画追不上内容**：每次数据变化重启一个 1500ms 定长 smooth 动画，目标是进函数时算死的 `scrollHeight + 1000`。长文本中途继续增长时动画终点落后。
3. **watch 时序坑**：watch 回调触发时 DOM 未更新，读到的 `scrollHeight` 是旧值。
4. **双重驱动打架**：自动滚动每帧写 `scrollTop` 触发 scroll 事件 → 联动滚动又把对面栏按 ratio 拖动，两股写入竞争；`isScrolling` 互斥锁挡不住 1500ms 动画期间的交叉触发。

### 目标

- **取消手动开关**。跟随与否完全自动：用户上滚 = 阅读模式（停止跟随），主动滚回底部 = 自动恢复跟随。
- **保留平滑滚动**：长文本瞬移观众视觉跟不上，缓动是刻意的阅读体验设计。
- **修复追不上、时序坑、双重驱动**三个工程问题。

### 非目标（Out of Scope）

- 不改后端与数据链路（WS / dispatch）。
- 不做虚拟列表；不做 DeepSeek 的"长回答 clamp"（直播字幕需要一直钉底，语义相反）。
- **[v2]** 不改 `pages/index-original.vue`：Classic UI 保留旧手动开关、继续独占 `config-auto-scroll` localStorage key，与新页面互不干扰（AppHeader 的 Classic 入口保持可达，属预期）。

## 二、核心机制

### 2.0 判定的基本事实

**[v2] 修正**：v1 声称"贴底恢复无污染源"，评审证伪——本项目存在多条**内容收缩/布局变化**路径，布局变化可以制造 `dist < 1` 而无需用户滚动：

| 路径 | 来源 |
|---|---|
| 内容收缩 | 矫正替换（`opti_text` 可短于原文）、WS 重连 `data.init` 整体替换、后端清空（周三 crontab `/api/clear`）、段落长度/字号切换重排 |
| 视口变化 | 窗口 resize、移动端地址栏收起、fullscreen 切换（`display:none` 互切） |
| 浏览器行为 | scroll anchoring（译文替换占位符时自动调整 scrollTop）、overscroll 橡皮筋（scrollTop 瞬时越界为负） |

因此正确的模型不是"找无污染的单一判据"，而是**把 scroll 事件按来源分类**（2.2），不同来源做不同的事：

| 事件来源 | 识别方式 | 允许的动作 |
|---|---|---|
| **布局变化** | 布局指纹变化（`scrollHeight`/`clientHeight` 与上次不同） | 只刷新几何快照与按钮显隐，**绝不改变跟随状态** |
| **程序写入** | 位移 ≈ 0（写入由 `programmaticScrollTo` 统一走，读回值即基线） | 只刷新按钮；**绝不作为联动源、绝不改状态** |
| **外部位移** | 位移超出噪声容差且几何未变 | 唯一能停止/恢复跟随的来源；向下贴底自愈、向上累计介入 |

平滑动画场景下"距底阈值判停"原理性不可用（动画半途距底本来就大，会把"内容增长导致的距底变大"误判为用户上滚——此前高度阈值方案失败的根因），故**停止跟随不使用任何几何阈值**，只认外部位移。

### 2.1 状态模型

**[v2]** 每栏一个 `LaneState`（非响应式，模板只依赖 `showJump` ref），杜绝中英两栏散落变量漂移：

```ts
interface LaneState {
  el: HTMLElement               // .chinese-article / .english-article 滚动容器
  isFollowing: boolean          // 初始 true
  lastWritten: number           // 最后已知 scrollTop（程序写入读回值 或 外部位移后的新基线）
  lastGeom: { h: number; ch: number }   // 布局指纹
  userDrift: number             // 向上累计外部位移（≤0）
  running: boolean              // 追赶循环是否活跃
  raf: number | null
  lastTs: number
  showJump: Ref<boolean>        // 跳底按钮显隐（响应式）
}
```

**停止跟随的作用域与联动开关绑定 [v2，修复 v1 状态机不闭合]**：

- `configSyncScroll` **开启**：确认介入后停两栏（联动会把另一栏拖离底部，单栏保持跟随会与联动打架）。
- `configSyncScroll` **关闭**：**只停源栏**——v1 的"停是全局"论据只在联动开启时成立；联动关闭时若停两栏，另一栏没有任何恢复路径（无 scroll 事件），状态机不闭合。
- 两栏状态允许分裂（一栏跟随一栏阅读），跟随栏行为不受阅读栏影响；分裂态下联动对跟随栏不生效（2.7 守卫）。切换联动开关本身不改变现有状态，只影响后续事件的行为。

符号约定（贯穿全文伪代码）：`other(lane)` = 双栏中的另一栏；`reducedMotion` = 响应式布尔（`matchMedia('(prefers-reduced-motion: reduce)')` + `change` 监听）；`syncRaf` / `pendingSync` = 2.7 联动合并器的帧句柄与源栏槽位；`clamp(x)` = `Math.min(Math.max(x, 0), maxTop)`。

### 2.2 scroll 事件分类协议（本设计的核心）

所有滚动容器共用唯一入口，处理顺序固定：

```ts
const EPS = 1        // 程序写入自身事件的噪声容差（px）
const DRIFT = 8      // 向上累计介入阈值（px），可调
const BOTTOM = 1     // 贴底判定（px）
const JUMP_AT = 52   // 跳底按钮显隐阈值（px，固定 CSS 像素）

function onScroll(lane) {                          // passive listener
  const el = lane.el
  const h = el.scrollHeight, ch = el.clientHeight
  const geomChanged = h !== lane.lastGeom.h || ch !== lane.lastGeom.ch
  lane.lastGeom = { h, ch }
  const maxTop = h - ch
  const top = Math.min(Math.max(el.scrollTop, 0), maxTop)   // clamp：防 rubber-band 越界值污染
  const dist = maxTop - top

  // ① 布局事件：内容收缩/视口变化（含钳制、scroll anchoring、display:none 切换）
  if (geomChanged) {
    lane.lastWritten = top              // 基线必须重置（钳制改变了位置）
    updateJumpBtn(lane, dist)           // 只刷按钮，绝不改 isFollowing
    return
  }

  const external = top - lane.lastWritten
  // ② 程序写入自身触发的事件（写入时 lastWritten 已读回，位移≈0）
  if (Math.abs(external) <= EPS) {
    updateJumpBtn(lane, dist)
    return                              // 不作联动源、不改状态
  }
  // ③ 外部位移（用户）
  lane.lastWritten = top
  if (external < 0) {                   // 向上 = 回看方向
    lane.userDrift += external
    if (lane.isFollowing && -lane.userDrift > DRIFT) stopFollow(lane)
  } else {                              // 向下
    if (!lane.isFollowing && dist < BOTTOM) resumeFollow(lane)   // 主动滚到底 → 自愈
  }
  updateJumpBtn(lane, dist)
  scheduleSyncIfEligible(lane)          // 2.7 联动（源栏已不跟随时）
}
```

要点：

- **布局指纹分类**同时解决：内容收缩假恢复（①分流）、钳制误判介入（①分流）、`display:none` 假恢复（隐藏→恢复时几何从 0 巨变，走①）、scroll anchoring（伴随内容变化，走①）。配合容器 `overflow-anchor: none`（3.2）双保险。
- **clamp** 解决 overscroll 橡皮筋：iOS/macOS 惯性越界为负的 scrollTop 先夹回 `[0, maxTop]` 再参与一切计算。
- **向上才累计、向下只挪基线**：来回抖动不漂移；慢速拖滚动条（每帧 <2px、无 wheel）也会在 `DRIFT/(每帧位移)` 帧内触发介入——解决 v1 的"慢拖拔河平衡态"死区。
- **[v2] 删除 v1 的两处错误**：v1 伪代码 `updateJumpBtn(el, dist >= 52)` 缺 `!isFollowing` 条件（追赶数千 px 时按钮闪现）；v1 2.3 末段"动画未运行时出现 scroll 一律视为介入"与伪代码矛盾（会自我打断）。统一以本协议为准，判定与 `running` 状态无关。

### 2.3 停止跟随：只认外部位移

- **唯一判据**：向上累计位移 `userDrift < -DRIFT` 且当前跟随中 → `stopFollow`。
- 停止方向不限上滚起因：滚轮、拖滚动条、中键 autoscroll、触摸、惯性 fling、键盘滚动（若发生）全部经 ②③ 自然分类，无入口遗漏。
- **无溢出容器天然豁免**（`scrollHeight == clientHeight` 时 `maxTop = 0`、位移恒 0）：v1 的"无效输入把跟随永久置 false"不再可能；内容从无溢出变为有溢出时，内容 RO 唤醒循环即恢复跟随。
- **[v2] 打断动画与停止跟随是两个操作**：
  - `stopFollow(source)`（状态转换）：本地操作 = cancel rAF + `isFollowing=false` + `userDrift=0` + 刷按钮；**联动范围在函数内实施**——`if (configSyncScroll.value) 本地操作(other(source))`（另一栏同样取消 rAF 与状态），联动关闭则只处理 source。
  - 输入监听（只剩 wheel-up，见 2.9）只做 `cancelLoop`（立即停动画、消除拉拽感），**不动 `isFollowing`**——后续实际位移走 ③ 确认。轻触、双击缩放、无位移输入因此不再误伤跟随。

### 2.4 恢复跟随：向下贴底自愈

- **判据**：非跟随态 + 本次外部位移向下（`external > 0`）+ clamp 后 `dist < BOTTOM` + 几何未变（能走到 ③ 即已保证）→ `resumeFollow`。
- 语义："最后一个使视口移动的操作是向下、且到达了底部"——内容收缩类被动贴底走 ① 被分流，不可能触发恢复；overscroll 在底部继续前推（`external > 0` 且贴底）视为"想贴底"，恢复，符合直觉。
- `resumeFollow`：`isFollowing=true`、`userDrift=0`、`lastWritten` 刷新、刷按钮、`ensureLoop`（从当前位置平滑追到最新底）。
- 跳底按钮点击 = `resumeFollow(该栏)` + `ensureLoop`，复用追赶动画平滑到底，无独立 smooth 实现。

### 2.5 追赶式缓动动画

**[v2] 修正 v1 伪代码三处错误**（`lastTs` 未初始化、未逐帧更新、τ=0 除零）：

```ts
const TAU = 300      // ms，时间常数
const MAX_DT = 50    // ms，后台标签页回前台防 k≈1 瞬移

function ensureLoop(lane) {
  if (lane.running || !lane.isFollowing) return
  lane.running = true
  lane.lastTs = performance.now()                 // ← 初始化
  lane.raf = requestAnimationFrame(ts => followLoop(lane, ts))
}

function followLoop(lane, ts) {
  const dt = Math.min(ts - lane.lastTs, MAX_DT)
  lane.lastTs = ts                                // ← 逐帧更新（v1 缺失，dt 会累计失真）
  const el = lane.el
  const target = el.scrollHeight - el.clientHeight   // 每帧重算，内容增长自动追
  const dist = target - el.scrollTop
  if (dist < BOTTOM) {
    programmaticScrollTo(lane, target)            // 精确贴底后停帧（省电）
    lane.userDrift = 0                            // 贴底即漂移清零（与"贴底=跟随"语义自洽，
                                                  //  防低幅误触跨长时间累计成介入）
    lane.running = false
    return
  }
  if (reducedMotion) programmaticScrollTo(lane, target)     // 独立分支，不参与除法
  else programmaticScrollTo(lane, el.scrollTop + dist * (1 - Math.exp(-dt / TAU)))
  lane.raf = requestAnimationFrame(t2 => followLoop(lane, t2))
}

function programmaticScrollTo(lane, top) {        // 全部程序写入的唯一入口
  lane.el.scrollTop = top                         // 浏览器自动 clamp
  lane.lastWritten = lane.el.scrollTop            // 读回：吸收钳制与舍入，随后自身事件走 ②
}

function cancelLoop(lane) {
  if (lane.raf !== null) cancelAnimationFrame(lane.raf)
  lane.running = false
}
```

- **τ = 300ms**：收敛时长为 `τ·ln(dist₀)`（v1 的"约 5τ≈1.5s"仅在 dist₀≈148px 时成立，更正）：一屏 ≈2.1s，数十屏 ≈3s；对数增长，先快后慢。
- **稳态滞后**：内容匀速增长速度 v 时约滞后 `v·τ`（实测量级 ~100px/s → ~30px），小于 `JUMP_AT`，不触发按钮，属预期。
- **reduced-motion**：`matchMedia('(prefers-reduced-motion: reduce)')` + `change` 监听（运行时切换生效），reduce 时每帧直接贴底（瞬移）。
- `.article-display` 必须保持 `scroll-behavior: auto`（现状显式声明，`ParagraphDisplay.vue:119`）——整个 lastWritten 模型依赖赋值立即生效，任何 `smooth` 都会使模型失效。**写入 spec 作为不变量约束。**

### 2.6 观察与统一几何刷新

- **内容 RO** 观察 `.article-body`（新增包裹层）：回调内自持上次观测高度 `roLastH`（隐藏期间无 scroll 事件，`lastGeom` 不反映 display:none 变化）。回调逻辑：`roLastH === 0 && h === 0`（隐藏中）→ 仅记录返回；`roLastH === 0 && h > 0`（恢复显示）→ 跟随中直接 `programmaticScrollTo` 贴底（避免一次无意义的全程长滚），**阅读态 `programmaticScrollTo(lane, min(lane.lastWritten, maxTop))` 恢复原位**——Chrome/Safari 在 display:none 恢复时会把 scrollTop 重置 0，`lastWritten` 即隐藏前的天然保存点；其余情况 → `updateJumpBtn` + 若跟随 `ensureLoop`。
- **容器 RO** 观察 `.article-display`：捕获窗口 resize / fullscreen class 切换导致的容器盒变化，回调 = `updateJumpBtn`（几何变化产生的钳制 scroll 由 ① 分流，此处只补"无 scroll 事件"的场景）。
- **`updateJumpBtn(lane, dist)`**：`lane.showJump.value = !lane.isFollowing && dist >= JUMP_AT`（v1 缺 `!isFollowing` 条件已修正）。调用点：onScroll 各分支、两个 RO 回调、`resumeFollow`/`stopFollow`、程序写入后——**按钮显隐是"事件 + 布局变化"双驱动**，修复 v1 "阅读模式下内容拉长后按钮永不出现"（scrollHeight 增长不触发 scroll 事件）。
- **[v2] 删除 v1 的 `refreshExpected` 钩子与 fullscreen/font-size 专项监听**：布局指纹 + 双 RO 已覆盖全部场景，无需第三套机制。
- **`.article-body` 布局契约**：`display: flow-root; width: 100%;`——防止 `.article-paragraph` 的垂直 margin 折叠到包裹层外，保证 RO border-box 与实际滚动内容一致；几何的最终权威仍是容器的 `scrollHeight`（followLoop 每帧读取）。

### 2.7 联动滚动（configSyncScroll 保留，机制重写）

**[v2]** 用单一 rAF 合并器取代"50ms 节流 + 150ms final sync"两层定时器（少一条写入路径就少一类竞态，旧 final sync 的 pending timer 在用户接管时会覆盖用户的缺陷不复存在）：

```ts
function scheduleSyncIfEligible(source) {          // 仅在 onScroll ③ 分支末尾调用
  if (!configSyncScroll.value || source.isFollowing) return
  const peer = other(source)
  if (peer.isFollowing) return                     // 分裂态：跟随栏不受联动影响
  pendingSync = source
  if (syncRaf === null) syncRaf = requestAnimationFrame(applySync)
}

function applySync() {
  syncRaf = null
  const src = pendingSync; pendingSync = null
  if (!src || !configSyncScroll.value || src.isFollowing) return
  const peer = other(src)
  if (peer.isFollowing) return
  const srcMax = src.el.scrollHeight - src.el.clientHeight
  const peerMax = peer.el.scrollHeight - peer.el.clientHeight
  if (srcMax > 0 && peerMax > 0)
    programmaticScrollTo(peer, (src.el.scrollTop / srcMax) * peerMax)
}
```

- 联动只在**双方都处于阅读态**时生效（跟随中两栏由各自追赶动画天然同步贴底，无需 ratio 联动——修复 v1 双重驱动）。
- **程序写入不作联动源**：peer 被同步写入后，其 scroll 事件走 ②（external≈0）直接 return，无回环、无 ping-pong——取代 v1 删除的 `isScrolling`/`scrollSource` 防回环机制。
- rAF 帧内重算 ratio（用源栏最新位置），连续滚动每帧最多写对面一次，停手即停，无残留定时器。
- 联动开关的 UI（AppHeader 菜单）不变。

### 2.8 跳底按钮（取代手动开关按钮）

- 显隐：`!isFollowing && dist >= 52`（1~52px 灰区 = 刚离底，不跟随但不显示按钮，DeepSeek 同款语义）。由 `updateJumpBtn` 双驱动（2.6）。
- 点击：`resumeFollow(该栏)`——追赶动画平滑到底，到底后 2.4 判定保持自洽。
- 无障碍 **[v2]**：中英双语 `aria-label`/`title`（"回到最新 | Jump to latest"）、`:focus-visible` 样式。
- fullscreen 单栏时仅该栏按钮有意义，逻辑按栏独立天然退化。

### 2.9 输入监听清单（v1 的第一层大幅裁剪）

| 监听 | 动作 | 去留 |
|---|---|---|
| `wheel` 且 `deltaY < 0`（容器上，passive） | 仅 `cancelLoop(该栏)`——立即消除动画拉拽感，**不改状态** | **保留**（唯一低延迟收益入口） |
| `wheel` 向下 | 无监听 | 位移走 ③：跟随态下向下位移只挪基线不介入（动画继续追，用户到底自然收敛）；阅读态下滚到底自愈恢复 |
| `touchstart` / 键盘 | 无监听 | **删除**（touchstart 误伤 tap/缩放；容器无 tabindex、键盘监听是死代码且挂 document 会误停）——触摸惯性、键盘滚动全部由 ②③ 兜底 |

## 四、边界情况

| 场景 | 行为 |
|---|---|
| 内容收缩（矫正替换/重连 init/`/api/clear`/段落重排） | 布局指纹分流 ①：只刷几何与按钮；被动贴底不恢复、钳制不误判介入 |
| 视口增大（resize/地址栏收起/字号减小） | 同上（clientHeight 变化走 ①） |
| 内容未撑满容器（`maxTop=0`） | 距底恒 0，无外部位移可能 → 恒跟随；此前的输入不可能误停 |
| overscroll 橡皮筋（scrollTop 越界） | clamp 后参与计算，不误停；底部前推视为"想贴底"，阅读态下恢复 |
| 慢速拖滚动条（无 wheel 事件） | userDrift 跨帧累计，`DRIFT/每帧位移` 帧内介入，无拔河死区 |
| 栏 `display:none`（对侧 fullscreen） | 隐藏：rAF 取消、无事件；恢复：容器 RO + 几何从 0 走 ①，跟随中由内容 RO 特例瞬移贴底（无长滚），阅读态保持原位 |
| `prefers-reduced-motion` | 独立分支瞬移；运行时切换经 matchMedia change 生效 |
| 后台标签页积压后回前台 | `MAX_DT=50ms` 防首帧 k≈1 瞬移；RO 唤醒后正常追赶 |
| WS 断线重连、数据回放 | 机制只看几何，对数据层无感知 |
| 组件卸载 / HMR | 全量清理（rAF/RO/listener/matchMedia） |
| SSR | 全部逻辑在 onMounted 后 |
| 极端长文本一次撑高数十屏 | 指数逼近先快后慢，时长 τ·ln(dist₀) ≈3s |
| 状态分裂（一栏跟随一栏阅读）+ 联动开 | 联动对跟随栏不生效（2.7 守卫），互不干扰 |
| 阅读态拖到底与内容收缩钳制同帧 | 走 ① 不恢复（"布局事件不改状态"不变量的可接受代价，窗口极窄）：待内容再增长后向下微滚或点按钮即恢复，非 bug |
| 双栏同帧外部位移 | 联动后到覆盖先到、丢一次联动帧，无回环，可接受退化 |

## 五、验收标准（手动测试清单）

**基础跟随**：

1. 直播流/mock 持续 append：平滑追赶贴底，无跳变、无慢半拍爬行；持续增长时滞后 ≲30px。
2. 长文本一次撑高多屏：平滑长距离滚动，不误停（回归高度阈值方案失败场景）。

**停止跟随（各入口逐一验证）**：

3. 滚轮上滚：动画立即停（无拉拽感），位移确认后进入阅读态，内容增长视口纹丝不动。
4. 拖滚动条慢拖 / 中键 autoscroll / 触摸滑动+惯性 / 键盘滚动（若可达）：同上；**慢拖不出现"钉在距底几十 px 拔河"死区**。
5. 无溢出时轻触/滚轮（无位移）：跟随不丢失；此后内容撑高恢复跟随。
6. 追赶动画中向下滚轮加速：不误停、动画继续追（向下位移不介入）。

**恢复跟随**：

7. 阅读态滚回底部（滚轮/拖动条/触摸任一）：该栏自动恢复，无需按钮。
8. overscroll 在底部继续前推：恢复跟随。

**内容收缩与布局变化（v1 全部漏掉）**：

9. 矫正替换使文本变短 / 断开重连触发 `data.init` 替换 / 切换段落长度 / 缩小字号：阅读态不假恢复、不拽回；跟随态平滑追到新底部。
10. 窗口拉大 / 移动端地址栏收起：被动贴底不假恢复。
11. fullscreen 切换：隐藏栏 rAF 取消；恢复显示跟随中瞬移贴底（无全程长滚）、阅读态保持原位。
12. 后台标签页积压内容后回前台：无瞬移，正常追赶。

**联动与双栏**：

13. 联动关：上滚中文栏，英文栏**继续跟随**（v1 会连带冻结——修复验证）；中文滚到底只恢复中文。
14. 联动开：阅读态滚一栏另一栏按比例跟随；程序写入（联动/追赶）不触发停止、无 ping-pong。
15. 分裂态（一栏跟随一栏阅读）下开联动：跟随栏不受影响。

**按钮**：

16. 阅读态内容拉长跨过 52px 后按钮**出现**（内容增长不触发 scroll 事件的场景）；跟随时（含大距离追赶中）按钮隐藏；点击平滑到底并恢复。

**状态机击穿组合**：

17. 挂载后、任何程序写入前直接拖滚动条（`lastWritten`/`lastGeom` 已按 3.1 初始化，正常介入）。
18. 拖滚动条期间持续追加字幕：rAF 不抢控制权（外部位移基线持续跟进）。
19. 跟随中快速连续 resize/切字号/切 fullscreen：无误停。
20. `prefers-reduced-motion` 切换：立即改为瞬移/恢复缓动。

## 六、设计决策记录

- **为什么停止跟随不使用几何阈值**：平滑动画下距底大小无法区分"用户上滚"与"动画未到/内容增长"，此前实践已失败；外部位移分类是唯一无歧义判据。
- **为什么恢复判定敢用几何（贴底）**：单独使用不安全（收缩可假恢复，v1 论断被评审证伪），但在"布局指纹分流 + 向下位移确认"之后安全——被动贴底到不了判定分支。
- **为什么布局指纹（scrollHeight/clientHeight 变化）能分流布局事件**：程序写入与用户滚动都不改变这两个值；一切使 dist<1 的"非用户"路径（收缩钳制、锚定、display:none）必然伴随它们变化。
- **为什么停两栏与联动开关绑定**：v1"停是全局"的论据（联动会拖离另一栏）仅在联动开启时成立；联动关闭时全局停导致另一栏无恢复路径、状态机不闭合（fable 发现）。
- **为什么删 touchstart/键盘监听只留 wheel-up**：touchstart 无法区分"滚动意图"与"tap/缩放"；键盘入口现状不可达；wheel-up 是唯一"比 scroll 早数帧、低延迟停动画"有感知收益的入口，且只做 cancelLoop 不改状态，无误伤面。
- **为什么联动改 rAF 合并器**：50ms 节流 + 150ms final sync 的 pending 定时器会在用户接管后写入陈旧位置（haiku 发现），且旧 `isScrolling` 锁无法区分程序/用户；rAF 每帧最多一次写入 + EPS 分支天然防回环，一揽子取代三者。
- **为什么保留 52px / 1px / 8px 三个阈值**：52px 按钮显隐（DeepSeek 同款，固定 CSS 像素）、1px 贴底判定、8px 向上累计介入（慢拖响应与噪声鲁棒的折中，可调）。
- **评审记录**：v1 经 opus / sonnet / haiku / fable 四模型独立评审，全部 P0（按钮冻结、touchstart 误伤、下滚误判+状态机不闭合、内容收缩假恢复、overscroll 误停、慢拖死区、expected 未初始化、无溢出卡死、旧定时器覆盖、伪代码三处笔误）与高置信 P1 已并入本版；报告全文见评审会话，结论已固化于上表与各节 [v2] 标注处。
