# 主日值守误报：本地遗留容器复活监控（2026-09-27）

## 现象

2026-09-27（主日）07:44:02 管理员收到值守告警：

```
· 转录服务 ✅ 可达（uptime 31167s）
· 音频源 ✅ 正常（峰值 -12.4 dB）
· 字幕 ❌ 最近 30 分钟未收到任何字幕（最近 无，正式 无）
```

但当时礼拜正常进行：音频正常（告警自己也显示 ✅）、**字幕实际在出**（观众页面正常）。

## 定位过程（关键：先取证再动手）

1. **mini 生产容器日志**：当天 07:40-07:43 宽限期 9 次探测全部"字幕=有"，07:43 判正常，**全程未发告警** → 生产监控无辜
2. `curl mini:8081/backend/api/status`：lastAt 实时更新 → listen 埋点在生产正常工作
3. 产物 grep `__livetransPipelineStatus`：只在共享 chunk runtime.mjs，单副本正确
4. **真凶在 home**：home 本机 Docker 的 `livetrans` 容器（2024-09-21 创建的项目早期本地部署，宿主 8082→3000，挂载 `frontend/.output` 到 /app，restart=always）当天 07:44:02 发出了告警（docker logs 实锤：字幕=无 → 60s 确认 → 已通知管理员）

## 根因链（三条件凑齐）

1. **挂载卷污染**：09-14 部署时 `sync-mini.sh -b` 在 home 本地 `yarn build`，新产物（含监控插件）写进 `frontend/.output`——即写进了这个遗留容器的挂载卷
2. **容器重启加载新代码**：09-26 ~15:00 容器随 WSL/Docker 重启被 always 策略拉起，node 重新加载 /app 读到带监控的新代码 → 监控激活，默认配置（周日 07:40-09:25 + 真实 tellme）
3. **结构性误报**：dispatch 的字幕 POST 发往 mini，home 本地容器自己永远收不到 listen 流量 → `lastAt` 恒 0 → 每主日 07:44 必然误报"字幕❌"（音频/转录状态是从 home:9091 拉的真实值，所以那两行是真的，反而更具迷惑性）

## 处置（2026-09-27 08:05，礼拜进行中完成）

- `docker rm -f livetrans`（home 本机操作，未碰 mini / 转录 tmux），8082 释放，转录链路验证无恙（流 ok、WS recording=true）
- 阻止了 09:27 将至的第二条误报（"仍在直播"）
- CLAUDE.local.md 本机 Docker 表已移除该容器，并注明"不要在本机用 frontend/docker-compose.yml 起容器"

## 教训

- **本地 build 会污染一切挂载 .output 的容器**：sync-mini.sh 的"本地 build → rsync"模式意味着遗留挂载容器会被动吃到新代码，且无人知晓
- **restart=always 的遗留容器是定时炸弹**：两年无害不代表永远无害，新功能（尤其带通知/定时任务的）会在它体内复活
- **监控类功能的"多实例"问题**：同份代码起 N 个实例就有 N 个监控在跑，只该有一个权威实例；排查告警先问"谁发的"（本例靠 docker logs 对时间戳秒定位）
- 生产监控（mini）当天判断完全正确，本次事故与监控代码本身无关，无需改代码
